# QuizStack 仕様書

記事のURLから4択クイズを生成し、1問ずつ出題して採点するアプリケーション。

この文書が**現行仕様の正**。仕様を変更したら必ずここを更新する。
`init.md` はフェーズ1の実装指示書として凍結してあり、現状とは一致しない。

---

## 1. 全体像

### 画面と遷移

```
未ログイン
  /login  ──────┐
  /signup ──────┤ 認証に成功
                ▼
ログイン済み
  /               ホーム（URL入力）
    ↓ 送信
  /generating     ローディング（ここで生成処理を実行）
    ↓ 完了で自動遷移
  /attempt/[id]           出題（1問ずつ）
    ↓ 全問回答
  /attempt/[id]/result    結果（スコアと全問の振り返り）

  /dashboard      ダッシュボード（学習状況）
```

### ルートグループ

| グループ | 対象 | 認証 |
|---|---|---|
| `(app)` | `/` `/generating` `/attempt/*` `/dashboard` | 必須。未ログインは `/login` へ |
| `(auth)` | `/login` `/signup` | 不要。ログイン済みは `/` へ |

`(app)` のレイアウトは共通ヘッダーを表示する。`(auth)` にヘッダーはない。

### モジュール

| モジュール | 責務 | 現在の実装 |
|---|---|---|
| `user` | 登録・認証・セッション | 本実装（Prisma + SQLite） |
| `content-extraction` | URLから本文を抽出 | **モック**（ネットワーク未使用） |
| `quiz-generation` | 抽出結果からクイズを生成 | **モック**（3問固定・遅延あり） |
| `quiz-session` | 出題・回答・採点 | ロジックは本実装、保存は**メモリ** |
| `analytics` | 学習状況の集計（ダッシュボード） | **モック**（固定データ） |

未着手: `quiz-catalog`（クイズの保管・検索）

## 2. 認証・認可

### 認証方式

メールアドレスとパスワード。OAuth は使わない。

ユーザーが持つ情報は **ユーザー名・メールアドレス・パスワード** のみ。

### 登録（`/signup`）

- 入力: ユーザー名 / メールアドレス / パスワード
- パスワードは **8文字以上128文字以下**、空白のみは不可
- メールアドレスは正規化（前後空白除去・小文字化）してから一意性を判定する
- 登録に成功するとそのままログイン状態になる
- 既に登録済みのアドレスは「このメールアドレスはすでに登録されています」

### ログイン（`/login`）

- 失敗理由は **「アドレスが存在しない」と「パスワードが違う」を区別しない**。
  区別すると登録済みアドレスの存在を総当たりで確認できてしまうため
- ユーザーが存在しない場合もハッシュ照合と同等の時間をかける（応答時間から推測させない）

### パスワードの保存

- Node 標準の **scrypt**。ソルトはユーザーごとにランダム
- 保存形式 `scrypt$N$r$p$<salt>$<hash>`。パラメータを同梱しているため、
  将来コストを引き上げても既存ハッシュを照合できる
- 照合は `timingSafeEqual`

### セッション

- ログインのたびに新しいトークンを発行する（セッション固定攻撃の防止）
- DBに保存するのは **トークンの SHA-256 ハッシュのみ**。平文は保存しない
- 有効期間 30日
- Cookie: `httpOnly` / `sameSite=lax` / 本番のみ `secure` / `path=/`
- ログアウト時はサーバー側のセッションを削除したうえで Cookie も削除する

### 認可

- `(app)` のレイアウトでログインを確認する。ただし**これは認可の境界ではない**。
  画面を出さないための措置であり、データに触れる各所（`api/` と Server Action）が
  あらためて所有者を確認する
- **Attempt は開始したユーザーのもの**。他人の挑戦は閲覧も回答もできない
- 他人の挑戦に対しては「権限がありません」ではなく **「見つかりません」** を返す。
  区別するとIDの総当たりで他人の挑戦の実在を確認できてしまうため
- 回答者はクライアントの申告ではなく**セッションから決める**

## 3. クイズの生成と出題

### ホーム（`/`）

- URL入力フィールドのみ。問題数の選択UIはない（常に3問固定のため）
- 送信すると `/generating?url=...` へ**ルート遷移**する（同一画面での状態切り替えはしない）

### 本文抽出（`content-extraction`）

現在はモックだが、モック・本実装のどちらでも次のドメインルールが適用される。

- **https 以外のURLは受け付けない**
- トラッキングパラメータ（`utm_*` `fbclid` など）を除去し、フラグメントを削除する
- 本文が **200文字未満**ならクイズを作れないものとして拒否する
- 本実装ではSSRガードを通す（プライベートIP・ループバック・リンクローカル・
  クラウドメタデータへのアクセスを、リダイレクトの各ホップで遮断する）

> モックはネットワークへアクセスせず、入力URLのホスト名から機械的に
> タイトルと本文を組み立てる。上記のルールは同じように適用されるため、
> `http://` や URL 形式でない文字列を入力するとエラーになる。

### クイズ生成（`quiz-generation`）

- 1問は **4択**。正解の番号は 0〜3
- 各問題は 問題文 / 選択肢4つ / 正解番号 / 解説 / 出典の抜粋（200文字以内）を持つ
- 1回の生成で **1〜5問**。モックは常に3問
- これらは生成元（モック / LLM）を問わず、生成時に検証される

### 出題（`/attempt/[id]`）

- 1問ずつ出題する。進捗（2 / 3）を表示する
- **正解と解説は回答前のクライアントに渡さない**。回答後のレスポンスで初めて渡る
- 回答すると即座に採点し、正誤・正解・解説を表示してから次へ進む
- 出題順どおりにしか回答できない
- 同じ問題には二度回答できない
- 全問回答した時点で自動的に終了し、スコアが確定する
  （「終了する」という操作は存在しない）

### 結果（`/attempt/[id]/result`）

- スコア（正答数 / 出題数）と全問の振り返り（設問・自分の回答・正解・解説）
- **完了していない挑戦の振り返りは取得できない**
- 出典のタイトルとURLを表示する

## 4. ダッシュボード（`/dashboard`）

学習状況を確認する画面。**表示データはすべてモック**（後述）。

### 構成

**1. サマリー統計**（カード2枚）

| 項目 | 内容 |
|---|---|
| 作成したクイズ | これまでに生成した問題の総数 |
| 通算正答率 | 全回答に占める正解の割合。回答数も併記する |

正答率は保存値ではなく、回答数と正解数から**常に導出する**。

**2. 学習の記録（芝生）**

GitHub のコントリビューショングラフに相当する表示。

- **当月を1枚のカレンダー状のマス目で表示**し、`‹` `›` で前後の月に切り替える
- 保持するのは当月を含む **直近13ヶ月**。範囲の端ではボタンを無効化する
- マスの濃さは、その日の回答数に応じた **0〜4の5段階**
  （0問 / 1〜2問 / 3〜4問 / 5〜7問 / 8問以上）
- 今日のマスには枠線を付ける
- ヘッダーに **通算学習日数**（1問以上答えた日の総数）、
  グリッド下にその月の学習日数を表示する
- 全月分のデータをサーバーから渡しているため、月の切り替えで再取得は発生しない
- **「今日」の判定と月グリッドの組み立てはサーバー側で確定させる**。
  クライアントで日付を取り直すとサーバー描画と食い違うため

**3. 直近の挑戦**（5件）

各行に 記事タイトル / ドメイン / スコア / 正答率 / 相対日時（「3時間前」）。

> **結果画面への遷移は付けていない。** モックの `attemptId` は実在せず、
> 遷移させても「見つかりません」になるため。挑戦がDBに保存されるように
> なった時点でリンクを追加する。

**4. 空状態**

クイズを1問も作っておらず、挑戦も0件の場合に表示する。
`lib/constants.ts` の `MOCK_DASHBOARD_IS_EMPTY` を `true` にすると確認できる。

### モックデータの性質

- **全ユーザー共通**。ユーザーIDは参照していないので誰が見ても同じ内容になる
- シードを固定した擬似乱数で生成するため、リクエストのたびに数字は変わらない
- 芝生の合計回答数と、サマリーの「回答数」は一致させている
  （別々に決めると「芝生は埋まっているのに回答数が少ない」といった矛盾が起きるため）

## 6. 設計上の決まりごと

### レイヤー

各モジュールは `domain` / `use-cases` / `infrastructure` / `presentation` / `api` に分かれ、
依存は必ず外から内へ向く。`domain` は他のどの層も import しない。

- **`domain/entities`** — ドメインのルールを**エンティティ自身が持つ**。
  不変条件は生成時（`create` / `of` / `start` など）に検証し、
  それを通らないインスタンスは存在できないようにする
- **`domain/rules`** — 副作用のない純粋関数
- **`domain/ports`** — 外部との接点のインターフェース
- **`use-cases`** — 取得 → エンティティに委譲 → 保存、の調整のみ。判断はしない
- **`infrastructure`** — ポートの実装。差し替え可能
- **`presentation`** — Server Action（`'use server'`）
- **`api`** — RSC から呼ぶ読み取り。画面向けの形に詰め替える

### モジュール境界

- 他モジュールへは **`index.ts` 経由でのみ** アクセスする
- `'use client'` なコンポーネントは **`actions.ts`** から import する。
  `index.ts` にはサーバー専用の依存（DIコンテナ経由の Prisma など）が
  含まれており、クライアントから import するとブラウザ側のバンドルに
  引き込まれてビルドが壊れる

### DI

- ポートと実装の結び付けは各モジュールの `container.ts` の1箇所だけ
- モックを本実装に差し替えるときは **bind 先を変えるだけ**で済むようにする
- 全モジュールのコンテナは `lib/container.ts` で束ねる

### エラー

- Server Action は例外を throw せず、必ず `ActionResult<T>`（成功/失敗の判別共用体）で返す
- `ErrorCode` とユーザー向け文言は `lib/errors.ts` に集約する

### その他

- TypeScript strict、`any` 禁止
- Server Component がデフォルト。`'use client'` は必要な末端のみ
- 入力の検証は境界で Zod。ただし Zod が見るのは「型どおりか」まで。
  業務ルールの判断はドメインが行う
- マジックナンバー禁止。`lib/constants.ts` に集約する

## 7. 未実装・保留

| 項目 | 現状 | 解消の条件 |
|---|---|---|
| 本文抽出が実物でない | HTTP取得と Readability の実装はあるが未接続・未検証 | `content-extraction/container.ts` の bind 変更 |
| クイズ生成がLLMでない | プロンプトと出力スキーマは用意済み・未接続 | `quiz-generation/container.ts` の bind 変更 |
| 挑戦がメモリ保持 | サーバー再起動・複数インスタンスで消える | `AttemptStore` のDB実装を追加 |
| ダッシュボードがモック | 集計元のクイズ・回答履歴がDBにない | `quiz-catalog` の新設と `DashboardRepository` のDB実装 |
| 履歴から結果画面へ飛べない | モックの attemptId が実在しないため | 挑戦のDB保存 |
| 復習機能がない | スキーマの `Quiz.lastIsCorrect` は用意済み | `quiz-catalog` の新設 |
| モジュール境界が機械的に強制されていない | `index.ts` 経由の規約はコメントのみ | ESLint の `import/no-restricted-paths` 等 |
| ダークモードが無効 | トークンは揃っているが `.dark` を付ける仕組みがない | テーマ切り替えの実装 |

### `quiz-generation` の domain 層が越境 import している

`domain/ports/quiz-generator.ts` が `content-extraction` の `ExtractedContent` に
依存しており、最も守られるべき層が他モジュールに繋がっている。

抽出結果は永続化しない方針が確定しているため独立モジュールとして立てる根拠は弱く、
`content-extraction` を `quiz-generation` に統合すれば解消する。未対応。
